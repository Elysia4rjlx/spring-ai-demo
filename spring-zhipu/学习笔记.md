## 一、Builder 模式（基础，贯穿全项目）

### Builder vs builder

| 写法 | 是什么 | 出现在哪 |
|---|---|---|
| `Builder`（大写） | **类型**（类/接口） | `ChatClient.Builder builder` 的参数类型 |
| `builder`（小写） | **方法**或**变量** | `ChatClient.builder(model)`、`builder.build()` |
| `build`（小写） | 出货方法 | `builder.build()` |

**口诀**：`Builder` 是名词（图纸），`builder`/`build` 是动词（造）。

### 点号 `.` 的两种用法（曾卡住的重点）

- `对象.方法()` → 点后面小写 + 括号 = 调用动作
- `ChatClient.Builder` → 点后面大写 + 无括号 = 类型定位，"ChatClient 里面的 Builder"
  - 类比 `Map.Entry`：同一个点号
  - 编译后磁盘上真的生成 `ChatClient$Builder.class`，`$` 就是"里面的"

### 什么时候注入 Builder，什么时候注入成品

- **注入 Builder**：配置需要在代码里定制（挂 Advisor、设 System Prompt）——如 `ChatClient.Builder`
- **直接注入成品**：配置 yml 就能定死——如 `ImageModel`、`TextToSpeechModel`
- 判断标准：看配置能不能写成键值对。能 → 成品；不能（要 Java 对象）→ Builder

### 手写的 Builder 骨架（理解原理用）

```java
public class Student {
    private final String name;
    private Student(String name) { this.name = name; }  // 私有，堵死 new

    public static StudentBuilder builder() { return new StudentBuilder(); }

    public static class StudentBuilder {
        private String name;
        public StudentBuilder name(String name) {
            this.name = name;
            return this;      // 返回自己 → 链式调用
        }
        public Student build() {
            return new Student(name);   // 封箱出货
        }
    }
}
```

## 二、图像生成（Image Model API）

### 六个对象与流水线

```
文字 → ImagePrompt（请求包）
         ├─ ImageMessage（文字的包装纸：text / weight / media / metadata）
         └─ ImageOptions（配置：model / n / format）
     → ImageModel.call()
     → 智谱 cogview-3-flash
     → ImageResponse（结果包）
     → ImageGeneration（一张图 + 元数据）
     → Image.getUrl()
     → 浏览器显示
```

**对称之美**：去程和回程结构一致——Prompt/Response 都是包，Message/Generation 都是包里一项，text/Image 都是真正的数据。

### 关键配置（本项目）

```yaml
spring:
  ai:
    openai:
      api-key: ${ZHIPU_API_KEY}
      base-url: https://open.bigmodel.cn/api/paas/v4
      image:
        model: cogview-3-flash    # 免费文生图模型
```

### 坑与结论

1. **`image.model` 在 2.0.3 里 yml 绑定未生效**（trace 日志显示实际用的是 `gpt-image-1-mini`）。
   - jar 元数据确认属性名正确、自动配置启用；但实测第一层没接上
   - **解决方案**：代码里显式写 `.model("cogview-3-flash")`，绕过 yml
2. `weight` 参数是 Stability AI 的正负提示词机制，**智谱/OpenAI 兼容接口忽略它**
3. `quality` / `style` 是 OpenAI 专属，智谱可能忽略——只给模型它认识的参数
4. base-url 写到 `/v4`，SDK 自动拼 `/images/generations`；**不要写全路径**

### 代码模板

```java
@RestController
@RequestMapping("/image")
public class ImageController {
    private final ImageModel imageModel;    // 接口注入，不绑具体厂商

    public ImageController(ImageModel imageModel) { this.imageModel = imageModel; }

    @GetMapping("/generate")
    public String generate(@RequestParam String prompt) {
        ImageResponse response = imageModel.call(
            new ImagePrompt(prompt, OpenAiImageOptions.builder()
                .model("cogview-3-flash")   // 显式写，绕开 yml 的坑
                .n(1)
                .responseFormat("url")
                .build()));
        return response.getResult().getOutput().getUrl();
    }
}
```

### ImagePrompt 的 5 个构造器

1. `new ImagePrompt(String)` — 最简，默认配置
2. `new ImagePrompt(String, Options)` — **最常用**
3. `new ImagePrompt(ImageMessage, Options)`
4. `new ImagePrompt(List<ImageMessage>, Options)` — 母构造器
5. `new ImagePrompt(List<ImageMessage>)`

前三个都是第 4 个的便捷委派（漏斗结构）。`String` 构造内部会自动 `new ImageMessage(...)`。

## 三、语音（Speech）

### 两个方向

| | ASR 语音转文字 | TTS 文字转语音 |
|---|---|---|
| 接口 | `TranscriptionModel` | `TextToSpeechModel` |
| 输入 | `Resource` 音频文件 | `String` 文字 |
| 输出 | `String` 文字 | `byte[]` 音频字节 |
| 智谱模型 | 待确认 | `glm-tts`（**收费**，图像才免费） |

### TTS 配置（2.0.3 扁平写法，jar 实证）

```yaml
spring:
  ai:
    openai:
      api-key: ${ZHIPU_API_KEY}
      base-url: https://open.bigmodel.cn/api/paas/v4
      audio:
        speech:
          model: glm-tts
          voice: female           # String 类型，不是枚举！可选 tongtong / chuichui
          response-format: wav
          speed: 1.0
```

`spring.ai.openai.audio.speech.options.*` 是废弃别名，扁平写法才是 2.0 正解（jar 的 configuration-metadata.json 实证）。

### TTS 代码

```java
@RestController
@RequestMapping("/speech")
public class SpeechController {
    private final TextToSpeechModel textToSpeechModel;

    public SpeechController(TextToSpeechModel textToSpeechModel) {
        this.textToSpeechModel = textToSpeechModel;
    }

    @GetMapping(value = "/tts", produces = "audio/wav")
    public void tts(@RequestParam(defaultValue = "你好") String text,
                    HttpServletResponse response) throws IOException {
        byte[] audio = textToSpeechModel.call(text);   // 一行出音频

        response.setContentType("audio/wav");
        response.setContentLength(audio.length);
        response.getOutputStream().write(audio);       // 字节流直写
        response.getOutputStream().flush();
    }
}
```

完整版（可读 metadata）：

```java
TextToSpeechPrompt prompt = new TextToSpeechPrompt(text);
TextToSpeechResponse resp = textToSpeechModel.call(prompt);
byte[] audio = resp.getResult().getOutput();
```

### TTS 完整链路（浏览器 → 模型 → 浏览器）

1. 浏览器发 `GET /speech/tts?text=你好`
2. DispatcherServlet 找到 `tts()`；`@RequestParam` 绑文字，`HttpServletResponse` 由专用解析器注入
3. `textToSpeechModel.call(text)` 一行
4. 框架内部：String → TextToSpeechPrompt → 合并 yml 配置 → POST `/v4/audio/speech` + Bearer token
5. 智谱合成音频，**返回二进制字节（不是 JSON）**
6. Controller 写入 `HttpServletResponse` 的 OutputStream，设 `Content-Type: audio/wav`
7. 浏览器播放

**关键**：音频是二进制流，不是 JSON，所以直接写 OutputStream，不转对象。

### 与课件的区别（语音）

| 环节 | 课件 1.x | 本项目 2.0.3 |
|---|---|---|
| 接口 | `SpeechModel` / `OpenAiAudioSpeechModel` | `TextToSpeechModel` |
| 请求 | `SpeechPrompt` | `TextToSpeechPrompt`（可省略） |
| 响应 | `SpeechResponse` | `TextToSpeechResponse`（可省略） |
| 调用 | `model.call(new SpeechPrompt(text, options))` | `model.call(text)` 一行 |
| voice | `Voice.ALLOY` 枚举 | `String "female"` |
| 配置 | `audio.speech.options.model` | `audio.speech.model` 扁平 |
| 输出 | MP3 | wav（智谱示例） |
| **底层流程** | 一样 | **一样** |

## 四、Spring MVC 参数绑定（面试常考）

官方原文：任何**简单值类型**（String、int 等）参数，若无注解、且没被其他解析器接走，被当作 `@RequestParam`。

- `String message` 不写注解也能绑定 URL 里的 `?message=xxx`
- 写注解是为了 `defaultValue` / `required` / 改参数名
- 参数名靠编译时 `-parameters` 保留，Spring Boot 父 POM 默认开启

| 注解 | 取值来源 | URL 形态 |
|---|---|---|
| `@RequestParam` | 查询参数 | `/generate?prompt=一只猫` |
| `@PathVariable` | 路径段 | `/generate/一只猫` |
| `@RequestBody` | JSON 请求体 | POST + body |
| 无注解的 `HttpServletResponse` | 容器直接给 | — |

## 五、排错记录（宝贵经验）

### 401 "模型不存在，请检查模型代码"

- 智谱返回的中文错误 → base-url 和 key 都对，问题在 `model` 参数
- 当时 yml 写的是 `glm-image`（那是异步接口 `/async/images/generations` 的模型），同步接口要 `cogview-3-flash`
- 改了 yml 仍报错 → 第一层配置就没进 bean → 显式 `.model(...)` 解决

### 排查方法论（通用）

1. 看错误文案语言判断是哪一层返回的
2. 用 curl 绕开 Java 直接测平台（定位平台 vs 代码）
3. 开 trace 日志看框架实际发出去的 model：`logging.level.org.springframework.ai.openai: trace`
4. 源码里那行日志是 **trace 级别**，debug 看不到

### Windows PowerShell 跑 curl 的坑

Linux 的 `\` 续行在 PowerShell 无效（要用反引号 `` ` ``），JSON 用单引号包裹。

### 环境变量

```yaml
api-key: ${ZHIPU_API_KEY}
```

IDEA 里配：Run → Edit Configurations → Environment variables。改 yml 后必须重启（环境变量只在进程启动时读取）。

## 六、万能规律总结

Spring AI 所有模型套同一个模板：

```
XxxPrompt → XxxModel.call() → XxxResponse → getResult().getOutput()
```

差别只在输出形态：聊天是文字、图像是 URL、语音是字节流。

**核心思想**：换平台只改 yml 的 base-url / model / key，业务代码不动——这就是统一抽象的价值。
